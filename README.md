# Трекер привычек — телеграм-бот

Бот для учёта полезных и вредных привычек: отметки по дням, ежедневные напоминания,
календарь месяца картинкой, приглашения друзей.

## Что умеет

- Несколько привычек у каждого пользователя; каждая — **полезная** или **вредная**, со своим эмодзи.
- Отметки за сегодня, за вчера и за любой день последнего года.
- Напоминание раз в день в заданное время по часовому поясу пользователя.
- Календарь одной привычки и общий календарь по всем привычкам — картинкой, с листанием месяцев.
- Личная ссылка-приглашение со счётчиком пришедших.
- «Поделиться» календарём: картинка, статистика и приглашение одним сообщением.
- Управление инлайн-кнопками; команды нужны только чтобы открыть меню.

## Быстрый запуск

Нужен [uv](https://docs.astral.sh/uv/); Python 3.14 он скачает сам (версия закреплена в
`.python-version`).

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Положите токен в `.env`:

   ```
   cp .env.example .env   # и впишите BOT_TOKEN
   ```

3. Запустите:

   ```
   uv run python -m habitbot
   ```

Бот работает через long polling: входящий адрес, домен и сертификат не нужны.

Чтобы работала кнопка «Выбрать чат», включите у бота встроенный режим: `/setinline` у
@BotFather и любой текст-подсказка, например «Поделиться календарём привычек…».

## Настройки

Переменные окружения или строки в `.env` рядом с местом запуска:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | Токен от @BotFather. Обязательна |
| `DATABASE_URL` | — | Адрес PostgreSQL: `postgresql://роль:пароль@хост:порт/база`. Если задан, используется он |
| `HABIT_DB` | `habits.db` | Путь к файлу базы SQLite — когда `DATABASE_URL` не задан |
| `DEFAULT_TZ` | `Europe/Moscow` | Часовой пояс для новых пользователей |
| `OPENROUTER_API_KEY` | — | Ключ OpenRouter для мотивационных сообщений. Без него мотивация работает на готовых фразах |
| `OPENROUTER_MODEL` | `~anthropic/claude-sonnet-latest` | Модель для мотивации; алиас указывает на последний Sonnet |

`.env` и `*.db` исключены из git.

## Как пользоваться

`/start` показывает меню; на каждом экране есть кнопка «☰ Меню», экран перерисовывается в том
же сообщении. Любой текст вне диалога тоже открывает меню.

| Кнопка | Что делает |
|---|---|
| 📋 Сегодня | Привычки в две колонки; нажатие меняет ответ за сегодня по кругу: да → нет → нет данных |
| 📚 Привычки | Список привычек; карточка — ответ за сегодня и вчера (кнопка на день, нажатие меняет ответ по кругу), календарь, напоминание, эмодзи |
| 🗓 Календарь | Общая картинка месяца по всем привычкам |
| ➕ Добавить | Название → полезная или вредная → эмодзи → время напоминания (или без него) |
| 🌍 Часовой пояс | Город кнопкой, либо название (`Europe/Berlin`) или смещение (`+3`) текстом |
| 🤝 Пригласить | Приглашение со ссылкой, счётчик пришедших, копирование и пересылка |
| ❓ Помощь | Короткая справка |

Время напоминания и эмодзи выбираются кнопками; своё время (`21:30`) и свой эмодзи можно
прислать сообщением. Текстом вводятся только название привычки и нестандартные значения.

Значки в разделе «Сегодня»: ✅ — сделано, ➖ — не сделано, ❗️ — вредная была, 💪 — вредной не
было, ▫️ — нет данных.

### Напоминания

- Одно на привычку, каждый день в заданное время.
- Полезная: «Пора: …» с кнопками «Сделано» и «Не сделано». Если привычка сегодня уже отмечена
  как сделанная, напоминание не приходит.
- Вредная: вопрос «как сегодня?» с кнопками «Не было» и «Было» — приходит всегда.
- Обе кнопки записывают ответ. Если не нажать ни одну, за день остаётся «нет данных».
- **На следующий день.** Переключатель «Когда: сегодня / завтра» на экране выбора времени (при
  добавлении привычки и в «⏰ Напоминание» на карточке): напоминание приходит в заданное время и
  спрашивает про вчерашний день, ответ записывается за него. Удобно, когда итог дня ясен только
  к ночи. Если за вчера ответ уже есть или привычка заведена сегодня, напоминание не приходит.
- **Включение и выключение.** В «⏰ Напоминание» на карточке — выключатель «✅ вкл / 🛑 выкл»
  в одном ряду с выбором дня. Выключенное напоминание не приходит, но время за ним сохраняется:
  включить обратно — одно нажатие. Выбор нового времени включает напоминание.
- День, про который спрашивали, записан в кнопках напоминания: нажатие после полуночи или через
  несколько дней попадёт в тот же день.
- Если бот в нужную минуту не работал, напоминание придёт при запуске, но не позже чем через
  полчаса после назначенного времени.

### Мотивация

Раздел «🔥 Мотивация» в меню. Рамка — теория самодетерминации: чем ближе мотивация к «хочу
сам», тем дольше держится привычка.

- **Стиль.** Человек выбирает, что ему ближе: 📈 цифры и прогресс, 🔥 серии, 🤝 поддержка,
  🧭 смысл, 🪞 идентичность («я такой человек»), ✨ интерес и новизна — или «🎲 подбирай сам».
  По умолчанию мотивация выключена. На `/start` бот один раз спрашивает «Что тебя
  мотивирует?» с этими кнопками и «Пропустить» — и новых, и пришедших раньше (флаг
  `users.motivation_asked`). После ответа сообщает, где поменять: «☰ Меню» → «🔥 Мотивация».
  Тем, кто пришёл раньше, вопрос можно разослать разом: `uv run python -m
  habitbot.ask_motivation` показывает, скольким он уйдёт, с `--send` — отправляет (повторный
  запуск никого не трогает).
- **«Зачем мне это».** Необязательная фраза своими словами (до 200 символов) — модель
  опирается на неё в стиле «смысл» и вообще, когда уместно.
- **Сообщение.** Короткий текст курсивом под вопросом напоминания, под кнопками ответа —
  «🪶 Мягче», «👍 Принято», «💥 Жёстче». Ответ на напоминание оставляет текст и кнопки отзыва,
  отзыв убирает кнопки отзыва. «Мягче» и «Жёстче» сдвигают тон следующих сообщений
  (пять ступеней, от «очень мягко» до «жёстко»), отзыв на сообщение принимается один раз.
- **Эксперименты.** 70% сообщений — в выбранном стиле, остальные — в других, включая
  «малый шаг» (модель Фогга: упростить, а не вдохновлять) и «выбор» (автономия). Вес стиля —
  доля сообщений, после которых привычку отметили за тот день, плюс бонус за «принято» и за
  этап привычки: первые две недели — лёгкость и поддержка, 2–5 неделя — прогресс и серии,
  дальше — идентичность и смысл. При «подбирай сам» так выбираются все сообщения.
- **Без стыда.** Ни в каком тоне нет вины и давления; после пропуска или срыва — поддержка и
  самый лёгкий шаг («не пропускай дважды»). Статистику о других людях модель не приводит.
- **Модель и запасной вариант.** Текст пишет модель через OpenRouter (`OPENROUTER_API_KEY`,
  по умолчанию последний Sonnet), с минимальными рассуждениями — около 2 секунд на сообщение.
  Если ключа нет, OpenRouter не ответил, ответ пустой или оборван по лимиту — берётся готовая
  фраза того же стиля с цифрами привычки (по две на стиль для полезных и вредных, отдельные —
  после пропуска). Готовые фразы тоже пишутся в журнал и получают кнопки отзыва.
- **Журнал.** Таблица `motivation_messages`: стиль, тон, эксперимент или нет, текст,
  источник (`llm` или `preset`), отзыв и отметка «после сообщения привычку отметили».

## Как считаются отметки

У каждого дня три состояния: «да», «нет» и «нет данных». «Да» и «нет» — это ответы, которые
дал человек (кнопкой напоминания, в разделе «Сегодня», на карточке или в календаре); «нет
данных» — ответа не было. В базе ответ — строка таблицы `marks` со значением 1 или 0, «нет
данных» — отсутствие строки.

- **Полезная**: «да» — сделано, «нет» — не сделано. Зелёный день — сделано, серый — не сделано.
- **Вредная**: «да» — было (сорвался), «нет» — не было. Красный день — было, зелёный — не было.
- **Нет данных**: день в пунктирной рамке. Под календарём привычки число таких дней за месяц
  показано отдельно от числа ответов «нет».
- Дни до начала учёта привычки и будущие не закрашиваются.
- **Серия**: у полезной — сколько дней подряд сделано (сегодняшний день без «сделано» серию не
  обнуляет), у вредной — сколько дней подряд без ответа «было». День без данных серию вредной
  привычки не прерывает: серия считает срывы, а не подтверждения.
- **Правка прошлых дней**: под календарём привычки кнопка «Изменить отметки» открывает плитку
  с числами месяца — нажатие меняет ответ по кругу: да → нет → нет данных. Отметить можно
  любой день за последний год, в том числе до заведения привычки: тогда учёт начинается с этого
  дня.

## Календари

**Календарь привычки** (из её карточки): сетка месяца, на отмеченных днях — эмодзи привычки,
сегодняшний день обведён. Листается на год назад. У вредной привычки под сеткой две плашки:
сколько дней без срыва сейчас и лучшая серия — самый длинный отрезок без срыва с начала учёта.
Они считаются на сегодня и не зависят от того, какой месяц открыт.

**Общий календарь** (кнопка в меню): в клетке дня — значки всех привычек, отмеченных в этот
день. Полезная на зелёной плашке, вредная на красной. В клетку помещается шесть значков, дальше
«+N». Под сеткой — легенда с числом отмеченных дней за месяц; у вредных привычек второй
строкой — дни без срыва сейчас и лучшая серия. Листается от месяца самой ранней
привычки до текущего.

Под обоими календарями — «Поделиться» и «Меню».

### Эмодзи на картинке

Берутся из системного шрифта: Apple Color Emoji на macOS, Noto Color Emoji на Linux
(`apt install fonts-noto-color-emoji`). На Linux они выглядят как в Android. Если шрифта нет,
календарь рисуется без эмодзи, только цветом. Составные эмодзи (флаги, семьи) не
поддерживаются — бот попросит выбрать другой.

## Приглашения и «Поделиться»

У каждого пользователя своя ссылка вида `https://t.me/<бот>?start=ref<id>`. Переход
засчитывается один раз — при первом входе нового человека; себе самому и повторно не
засчитывается. Приглашавший получает уведомление.

В разделе «Пригласить»:

- текст приглашения, где ссылка зашита в название бота;
- «Прислать для пересылки» — то же приглашение отдельным сообщением с кнопкой-ссылкой;
- «Скопировать текстом» (ссылка видна — для других мессенджеров) и «Скопировать ссылку»;
- «Поделиться» — выбор чата с готовым текстом.

«Поделиться» под календарём присылает отдельное сообщение: та же картинка, статистика за
показанный месяц (у одной привычки — отметки и серия, у общего календаря — строка на каждую
привычку, не больше десяти) и приглашение с кнопкой-ссылкой. Его можно переслать обычной
пересылкой. Следом приходит кнопка «Выбрать чат»: она открывает список чатов и отправляет тот
же календарь от имени пользователя — для неё нужен встроенный режим бота.

## Устройство

| Файл | Что в нём |
|---|---|
| `habitbot/__main__.py` | Запуск: чтение `.env`, бот, диспетчер, цикл напоминаний |
| `habitbot/bot.py` | Все экраны, кнопки и диалоги (aiogram 3) |
| `habitbot/db.py` | Хранилище (PostgreSQL или SQLite): пользователи, привычки, отметки, приглашения; расчёт серий |
| `habitbot/migrate.py` | Перенос данных из файла SQLite в PostgreSQL |
| `habitbot/reminders.py` | Цикл напоминаний раз в 30 секунд, разбор времени |
| `habitbot/motivation.py` | Мотивация к напоминаниям: стили, выбор стиля с экспериментами, запрос к модели, готовые фразы |
| `habitbot/calendar_image.py` | Отрисовка календарей (matplotlib, эмодзи через Pillow) |
| `tests/` | Логика и сценарии бота целиком на подставном Telegram |

База — PostgreSQL на сервере и SQLite (один файл) при локальном запуске и в тестах; запросы
общие для обеих. Схема создаётся при запуске; файл SQLite от прежней версии дополняется на
месте. Даты и время хранятся текстом в формате ISO. Состояние диалога («жду название») хранится в памяти и
сбрасывается при перезапуске; привычки и отметки при этом не теряются.

Кнопки удаления привычки в боте нет. Обработчик удаления остался для кнопок на старых
сообщениях: он скрывает привычку, отметки в базе остаются.

О пользователе хранится: идентификатор Telegram, имя и ник (обновляются при каждом обращении к
боту), часовой пояс, кто пригласил, дата и время первого прихода (UTC). У тех, кто пришёл до
появления этой записи, время первого прихода пустое.

## Деплой на сервер

Ниже — как бот развёрнут сейчас: Ubuntu 22.04, служба systemd, отдельный пользователь без прав
root, база — PostgreSQL. Адрес сервера в репозитории не хранится; в командах он обозначен
`<сервер>`.

| Что | Где |
|---|---|
| Код, окружение, токен, адрес базы | `/opt/habit-bot` (`.env`) |
| База | PostgreSQL 16 в контейнере `rag-pg` (общий с другим проектом), база `habitbot`, роль `habitbot`; слушает только `127.0.0.1:5432` |
| Копии прежней базы SQLite | `/opt/habit-bot/habits*.db` — после переезда не обновляются |
| Служба | `habit-bot` (`/etc/systemd/system/habit-bot.service`) |
| Пользователь | `habitbot` (системный, без входа) |
| Python и пакеты | `/opt/habit-bot/.python`, `/opt/habit-bot/.venv` |

Бот должен работать только в одном месте: два процесса с одним токеном мешают друг другу.
Перед запуском на сервере остановите локальный.

### Первая установка

Все команды — на сервере от root, кроме отмеченных.

1. Пользователь, папка, `uv` и шрифт эмодзи:

   ```
   useradd --system --home /opt/habit-bot --shell /usr/sbin/nologin habitbot
   mkdir -p /opt/habit-bot
   curl -LsSf https://astral.sh/uv/install.sh | env UV_INSTALL_DIR=/usr/local/bin INSTALLER_NO_MODIFY_PATH=1 sh
   apt-get install -y fonts-noto-color-emoji
   ```

2. Код — со своей машины, из папки проекта:

   ```
   git archive HEAD | ssh root@<сервер> 'tar -xf - -C /opt/habit-bot'
   ```

3. Токен — тоже со своей машины:

   ```
   scp .env root@<сервер>:/opt/habit-bot/
   ```

4. База в PostgreSQL — отдельная роль и база, пароль придумайте свой:

   ```
   docker exec rag-pg psql -U postgres -c "CREATE ROLE habitbot LOGIN PASSWORD '<пароль>'"
   docker exec rag-pg psql -U postgres -c "CREATE DATABASE habitbot OWNER habitbot"
   docker exec rag-pg psql -U postgres -c "REVOKE ALL ON DATABASE habitbot FROM PUBLIC"
   echo 'DATABASE_URL=postgresql://habitbot:<пароль>@127.0.0.1:5432/habitbot' >> /opt/habit-bot/.env
   ```

   Таблицы бот создаст сам при первом запуске.

5. Права и зависимости:

   ```
   cd /opt/habit-bot
   chown -R habitbot:habitbot .
   chmod 600 .env
   sudo -u habitbot env HOME=/opt/habit-bot \
     UV_PYTHON_INSTALL_DIR=/opt/habit-bot/.python UV_CACHE_DIR=/opt/habit-bot/.cache/uv \
     uv sync --no-dev
   ```

6. Служба — файл `/etc/systemd/system/habit-bot.service`:

   ```ini
   [Unit]
   Description=Habit tracker Telegram bot
   After=network-online.target
   Wants=network-online.target

   [Service]
   User=habitbot
   Group=habitbot
   WorkingDirectory=/opt/habit-bot
   Environment=HOME=/opt/habit-bot
   Environment=MPLCONFIGDIR=/opt/habit-bot/.cache/mpl
   ExecStart=/opt/habit-bot/.venv/bin/python -m habitbot
   Restart=always
   RestartSec=5
   NoNewPrivileges=true
   PrivateTmp=true
   ProtectSystem=full
   ProtectHome=true

   [Install]
   WantedBy=multi-user.target
   ```

   ```
   systemctl daemon-reload
   systemctl enable --now habit-bot
   ```

Служба поднимается после перезагрузки сервера и перезапускается при падении.

### Обновление

Со своей машины, из папки проекта:

```
git archive HEAD | ssh root@<сервер> 'tar -xf - -C /opt/habit-bot && chown -R habitbot:habitbot /opt/habit-bot && systemctl restart habit-bot'
```

Если менялись зависимости (`pyproject.toml`, `uv.lock`), перед перезапуском выполните на сервере
`uv sync --no-dev` той же командой, что в шаге 5. Базу и `.env` обновление не трогает.

### Эксплуатация

```
systemctl status habit-bot          # состояние
journalctl -u habit-bot -f          # журнал в реальном времени
journalctl -u habit-bot --since today
systemctl restart habit-bot         # перезапуск
systemctl stop habit-bot            # остановка
```

В журнале при запуске есть строка `storage: postgresql` — по ней видно, с какой базой бот
работает. Если `DATABASE_URL` пропадёт из `.env`, бот молча начнёт с файла SQLite.

Резервная копия базы — на сервере:

```
docker exec rag-pg pg_dump -U postgres -Fc habitbot > /root/backups/habitbot-$(date +%F).dump
```

Восстановление в пустую базу: `docker exec -i rag-pg pg_restore -U postgres -d habitbot < файл.dump`.
Автоматических копий нет.

Зайти в базу: `docker exec -it rag-pg psql -U postgres -d habitbot`.

### Перенос данных из SQLite

Если бот раньше работал на файле SQLite:

```
systemctl stop habit-bot
cd /opt/habit-bot
sudo -u habitbot .venv/bin/python -m habitbot.migrate habits.db 'postgresql://habitbot:<пароль>@127.0.0.1:5432/habitbot'
# затем добавить DATABASE_URL в .env и запустить службу
systemctl start habit-bot
```

Скрипт переносит все таблицы с теми же идентификаторами, сверяет число строк и ничего не пишет
в непустую базу.

Смена токена: впишите новый в `/opt/habit-bot/.env` и перезапустите службу.

### Вместо systemd — pm2

Если на сервере принято вести процессы в pm2:

```
systemctl disable --now habit-bot
cd /opt/habit-bot
MPLCONFIGDIR=/opt/habit-bot/.cache/mpl pm2 start .venv/bin/python --name habit-bot --interpreter none -- -m habitbot
pm2 save
```

В этом случае бот работает от того пользователя, под которым запущен pm2.

## Проверки

```
uv run ruff check .
uv run pytest
```

Тесты не обращаются к Telegram: сценарии подаются в диспетчер, сетевой слой подменён. По
умолчанию они идут на SQLite в памяти. Чтобы прогнать их на PostgreSQL, задайте
`TEST_DATABASE_URL` с адресом **отдельной тестовой** базы — тесты очищают в ней таблицы.

## Ограничения

- Напоминание одно на привычку и каждый день; выбора дней недели нет.
- Бот открыт для всех, кто найдёт его по имени; данные у каждого пользователя свои.
- Список пришедших по приглашению в боте не показывается — только их число; сами данные
  (имя, ник, время прихода) уже сохраняются.
- Кнопки копирования и «Выбрать чат» зависят от версии приложения Telegram; в старых могут не
  отображаться.
- Состояние незавершённого диалога теряется при перезапуске бота.
